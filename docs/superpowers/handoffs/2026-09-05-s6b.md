## Rulings taken with Kevin (brainstorm, approved in chat)

- **Q1 — one memory, trust-ordered supersession.** A scope is a list of
  stores in trust order, most trusted first (the operator builds it
  private-then-working). Supersession is computed over the scope; a belief
  supersedes across stores only from a store of equal or higher trust; a
  lower-trust belief is listed beside, never marks a higher one superseded.
- **Q2 — cites stay store-free; one rule.** Resolve in the first store in
  scope order holding the identity; the cache never overwrites; every
  rendered cite carries the store it resolved in; `retract` on a cite whose
  copy is not in the write store is refused by name. The model names
  subjects, never stores.
- **Q3 — the transaction axis is the shared clock's epoch; S6b waits on
  #347.** Until it lands, wall clock (one image per scope). The memory
  image opens one system clock and attaches its stores; decisions record
  their commit epoch from this unit on.
- **Approach A** — scope-aware memory layer: `:scope` keyword on `recall`,
  `conclude`, `resolve-cite`, `decisions-citing`, `trace` (default
  `(list graph)`); tools pass the scope. B (agent-layer merge) and C
  (derivation-first via rules S3) rejected — C leaks private existence
  into the working store.

## Design sections approved so far (1–6 of 7)

**1. Scope and trust order (approved).** `cl-llm/memory` gains a scope:
open stores in trust order. Resolution = first store in scope holding the
identity, answer names the store. Supersession direction = from no-later
in scope order. A multi-store scope requires every store attached to ONE
system clock; `%check-scope` refuses a mixed or clockless multi-store
scope (one regime, not two); a single-store scope needs no clock. Scope
reads run under one read snapshot per store, own store first, via a
helper (`call-with-scope-snapshots`); a scope read inside an open write
transaction is refused up front. `%check-scope`: open stores, no
duplicates, distinct `store-name`s, one shared clock when >1, write store
in the list; shared with `agent:make-scope`.

**2. `recall` over a scope (approved).** One series table over the union;
ordering unchanged; `superseded-by` = earliest-starting current claim in
the series starting later AND in a store no later in scope order;
`current-p` = open in its own store AND not superseded within scope under
that rule. `belief-record` gains its store; JSON `"store"` is the record's
own and `"superseded-by"` carries the successor's store. Filters/`:at`
applied per store before the merge. Nothing written. Kevin declined a
"contested" state (YAGNI). Test: split series both directions.

**3. `conclude` with a scope (approved).** Before its transaction opens, a
scope read of the proposal's series under the trust rule. No prior
anywhere → unchanged. Prior in the write store → the validator, as
today. Prior only in a HIGHER-trust store → refused with a new refusal
family `scope-conflict` (attempted + refused claims naming the
conflicting cite and store). Prior only in a LOWER-trust store → write
proceeds; the trace records the overridden cite/store as evidence.
Advisory like the validation report; the commit stays the enforcement.
`conclude-absence` same path. Kevin chose refusal on higher-trust conflict
(the injection shape the boundary exists for).

**4. Cites (approved).** `resolve-cite cite &key scope at` resolves
first-in-scope under snapshots, names the store; `:absent` when none.
Agent cache first-wins, same order as the scan. Every rendered cite
carries its store (`recall` rows already do; `retrieve` items, evidence,
`decisions-citing` gain it). `retract` refused by name when the resolved
copy is not writable. `trace` keeps resolving evidence in the store its
record named (`method` slot).

**5. Decisions across the scope (approved).** `decisions-citing` returns
`(id . store-name)` pairs (JSON gains `"store"`); `trace graph id &key
scope` resolves the decision first-in-scope (replica duplicates: Latent,
documented); `trace-listing` and `annotate-banners` pass the scope
(closes #47). `%write-evidence` dedupes on `(cite . store)` (#51).
`retrieve`'s claim doc id includes the store, as the absence path does
(#49). Every new decision records its commit `epoch` (NIL for older
records); `trace`'s as-of and `changed-since` move to it once #347 lands.

**6. Testing (approved).** Red-first against the single-store code,
each test named for the mechanism. A two-store fixture (one system clock
opened first, `private` and `working` attached, scope private-first);
single-store fixtures untouched. One test per `%check-scope` refusal plus
the clockless single-store positive case. Scope read inside an open write
transaction refused before any engine call. Trust rule both directions
(#46) with the reversed scope as the control. `conclude` (#50): higher-
trust prior refused as `scope-conflict`, nothing written anywhere; lower-
trust prior proceeds with the overridden cite/store as evidence; write-
store prior still goes to the validator. Cites (#48): first-in-scope,
cache first-wins, `retract` refused by name. Decisions (#47, #51, #49).
Epoch: two concludes on different stores record increasing integer
epochs; as-of-epoch reads are tested with #347's consumer, not here.
Memory and agent suites run foreground, one at a time, check counts in
the ledger; CI `test` workflow on the PR.
