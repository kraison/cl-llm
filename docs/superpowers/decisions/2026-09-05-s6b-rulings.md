## Taken while planning

1. `belief-record` gains `store` and `superseded-by-store` (graphs): the
   JSON `"superseded-by"` object needs the successor's store. One slot
   to remove if wrong.
2. `decision-record` gains `store` (a store-name string) beside `epoch`,
   so the trace tool's `"store"` survives the deletion of the agent's
   store search. One slot.
3. `resolve-cite` takes no snapshot of its own -- REVERSED by the final
   review: it scans the scope, so it now runs under the scope's
   snapshots and the transaction guard like every reader.
4. A higher-trust prior refuses even when the proposal names the same
   object; the boundary, not idempotence, is the point (spec SS5). One
   refused duplicate the model reads as a conflict.
5. The recall tool calls `recall` on the write store with the whole
   scope; the write store is always in the scope. No cost.

## Taken while executing

6. **The two-clocks test builds its own stores.** A third open graph
   under a name the fixture holds collides on the engine's per-name
   store id. One test.
7. **Fixtures bind their graphs NIL before one `unwind-protect`** so a
   failing second `make-graph` cannot leak the first store (Task 1
   review). The image-wide collision cascade otherwise.
8. **Every reader asserts its positional graph is in the scope** via
   `check-scope`'s membership check (spec SS3). One keyword per call.
9. **The recall tool and the retrieve tool seed the cite cache in scope
   order**, not row or ranking order: first-wins must mean
   first-in-scope (spec SS6). Found by the Task 3 test. One loop each.
10. **#51 is a documented bound, not two rows.** The trace family's
    unique identity (producer, decision, relation, cited cite) excludes
    `method`, where the store name rides; two evidence rows for one cite
    collide. One row per cite per decision, the first store in scope
    order naming it. Rejected: folding the store into the identity or
    making the family temporal -- a migration of the real store.
    Recorded on #51 and in spec SS7. A later schema unit if wrong.
11. **`conclude`'s `check-scope` sits after the transaction guard** (the
    brief's placement); error precedence only.
12. **Plan typos fixed in place**: `claim-current-p` on a recall row
    (unwrap with `belief-record-claim`); bare `retract-belief` outside a

13. **The retrieve-cache test gained a confound claim** so fusion ranks
    the two copies apart; with the plan's literal data RRF ties resolved

    the non-vacuity proof.
14. **Final review, one fix wave**: `resolve-cite` snapshotted and

## What the model sees differently after this unit

- `recall` rows carry `"store"`; `"superseded-by"` is an object
  `{"cite", "store"}` (was a cite string); `"current"` is false when a
  claim is superseded anywhere in scope under the trust rule.
- `decisions-citing` entries carry `"store"`; `trace` and `conclude`
  results carry `"epoch"` (omitted for a decision older than the clock).
- A `conclude` governed by a higher-trust store's prior is refused with
  the `scope-conflict` family naming the cite and its store.
- `retrieve`: a fact held by two stores is two items.
- `recall`, `trace`, `trace-listing`, `decisions-citing` and
  `resolve-cite` signal inside an open write transaction.
